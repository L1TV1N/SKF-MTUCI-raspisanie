# расписание скф мтуси

расписание занятий студентов скф мтуси в нормальном виде, вместо сканов pdf на сайте, выбираешь группу,
преподавателя или аудиторию и сразу видишь неделю, что идёт сейчас, что дальше и где, всё лежит в sqlite,
сервер на голом питоне без единой зависимости, фронт, один html, один css и один js без сборки, дизайн,
montserrat и фиолетовая палитра мтуси.

## как это работает

на сайте https://skf.mtuci.ru/uch_rab/time-table/ расписание выложено помесячно, отдельным pdf на каждую
группу, и это сканы без текстового слоя, скопировать оттуда нельзя, поэтому все 19 групп очной формы
(1–4 курс, сентябрь 2026) я перенёс руками в `data_src/<группа>.tsv`, дословно как в документе  дата,
пара, дисциплина, преподаватель, ассистент, аудитория, вид занятия, при первом запуске `db.py` заливает
это в `data/raspisan.db`, «иностранный язык 1 п/г» превращается в подгруппу 1, «семин.» в семинар, курс
считается по коду группы (дб2601  набор 2026, значит 1 курс).

<img width="1915" height="962" alt="Снимок экрана от 2026-09-23 17-57-48" src="https://github.com/user-attachments/assets/be6868cd-aa3e-4a84-bfdc-c3c4476261a5" />

получилось 1193 занятия, 34 преподавателя с ассистентами, 55 дисциплин, 21 аудитория, звонки настоящие,
7 пар с 08:30 до 20:15 и перерывом 13:20–13:50.

общие пары нескольких групп (потоковые лекции, физра, семинары) показываются одной карточкой с пометкой
«поток», у преподавателя его неделя собирается по всем курсам сразу, ассистент видит пары, где он помогает,
плашка «идёт 5-я пара, до конца 33 минуты» считается по московскому времени, а не по часам телефона, так что
у всех одинаково, неделю можно выгрузить в календарь `.ics` на весь семестр или распечатать на а4, ссылки
вида `/#/group/5` можно кидать в чат группы.

## запуск

```bash
python3 server.py
```

открываешь `http://localhost:8090`, нужен только python 3.11+, ничего ставить не надо, порт, адрес и
путь к базе меняются через `RASPISAN_PORT`, `RASPISAN_HOST`, `RASPISAN_DB`.

## админка

кнопки на главной нет специально, админка открывается по адресу `http://localhost:8090/admin`, пароль
по умолчанию `admin`, при старте сервер об этом предупреждает, свой задаётся так:

```bash
RASPISAN_ADMIN_PASSWORD='длинный-пароль' python3 server.py
```

там можно править занятия группы (по датам, как публикует скф, или еженедельные, если когда-нибудь
понадобится числитель/знаменатель), ставить замены и отмены на конкретный день, вести справочники групп,
преподавателей, аудиторий и дисциплин, менять звонки и параметры семестра, при сохранении сервер сам
проверяет пересечения  группа, преподаватель, ассистент, аудитория, и не даёт поставить две пары в одно
место, если только это не поток, спортзал и «дистанционно» помечены как аудитории, где можно параллельно.

## на сервер

живёт на своём vps за nginx, питон слушает только `127.0.0.1:8090`, наружу смотрит nginx, всё нужное
лежит в `deploy/`  юнит systemd, конфиг nginx с ограничением на подбор пароля админки и два скрипта,
выкладка идёт по ssh-ключу, без паролей:

```bash
deploy/deploy.sh <ip-сервера> litvinskiy-dev.online
```

скрипт заливает код в `/opt/raspisan`, ставит python3 и nginx, заводит системного пользователя `raspisan`,
поднимает сервис и при первом запуске генерирует пароль админки в `/etc/raspisan.env`, база живёт отдельно
в `/var/lib/raspisan`, поэтому повторный деплой её не трогает и правки из админки не пропадают, https
потом добавляется одной командой `certbot --nginx -d litvinskiy-dev.online -d www.litvinskiy-dev.online`,
когда домен уже смотрит на сервер.

## обновить расписание

когда на сайте появится октябрь  дописываешь строки в `data_src/*.tsv` и пересоздаёшь базу, либо правишь
через админку:

```bash
rm -r data/ && python3 server.py
```

база заполняется только один раз, при создании, так что если удалить все группы в админке, после
перезапуска они сами не вернутся.

## тесты

```bash
python3 -m unittest discover -s tests -v
```

39 тестов поднимают настоящий сервер на временной базе и гоняют всё подряд, загрузку всех 1193 занятий,
сверку со сканами, потоки, подгруппы, ассистентов, пересечения, замены, календарь, вход и сессии, правку
справочников, миграцию старой базы и попытки вылезти за пределы папки `static/`.

## api

- `GET /api/meta`  справочники, звонки, текущая неделя
- `GET /api/schedule?group=ID&date=ГГГГ-ММ-ДД`  неделя с заменами, вместо `group` можно `teacher` или `room`
- `GET /api/export.ics?group=ID`  календарь на семестр
- `POST /api/login`, `POST /api/logout`  вход в админку, сессия в httponly-куке
- `/api/admin/{groups,teachers,rooms,subjects,lessons,changes}`  get/post, `/ID`  put/delete
- `PUT /api/admin/bells`, `PUT /api/admin/settings`  звонки и семестр

если занятие с чем-то пересекается, сервер отвечает 409 со списком `conflicts`, повтор с `"force": true`
сохраняет всё равно.

## честно о ограничениях

это не официальный сервис мтуси, а перенос их pdf, и перенос ручной, я сверял его перекрёстно, общие пары
разных групп совпадают по времени и аудитории в сканах разных групп, но опечатку до конца исключить нельзя,
при расхождениях прав сайт, в самих документах тоже есть странности, «карпов д.а.» в шести местах стоит в
двух аудиториях одновременно (например 03.09 на 2-й паре лекция по истории в 402 и физра в 217, скорее
всего это два разных человека с одинаковыми инициалами), а у дмо2601 30.09 линейная алгебра поставлена
в спортзал, я оставил как в источнике. сейчас есть только сентябрь и только очная форма, заочку, экзамены
и гиа не переносил, у преподавателей только инициалы, потому что так в сканах, сессии админки живут
в памяти и сбрасываются при перезапуске, а пароль `admin` по умолчанию годится только для локального
запуска, в сеть без своего пароля и https через nginx или caddy это выставлять не стоит.
